## 1. 조사 — 지금 무엇이 있고 무엇이 묶여 있나

### 1.1 이미 있는 것 (클립이 올라설 자리)

| 있는 것 | 자리 | 클립에 주는 것 |
|---|---|---|
| 씬 = 오브젝트 여럿(무대·층·자리·오프셋·보이기·초상) + 카메라 | `Model/SceneAsset.cs` | 클립의 **시작 상태**. 새 모델을 짓지 않는다 |
| 씬 → 트리, 오브젝트마다 슬롯 접두사(`s1/…`) | `ScenePreview.Build` | 여러 오브젝트가 한 트리에 선다. 접는 순서(깊이 → 자리 → 오프셋 → 카메라)가 런타임과 같다 |
| 모션을 접두사로 오브젝트 하나에 얹기 | `MotionPreview.Pose(template, motion, t, isMuted, keyPrefix)` | 같은 함수를 오브젝트마다 부르면 된다. 반환 트리가 다음 호출의 template이 될 수 있다 |
| 모션은 rigKind의 것, 오브젝트는 입혀 볼 자리 | `ScenePreview.CanWear` | 클립의 "배역 ↔ 모션" 맞춤 검사 |
| commit 종점 = 마지막 키의 클레임 | 코어 `MotionMath.ClaimFor` · 리듀서 `ApplyMotion` | 앞 블록이 남긴 것이 뒤 블록의 시작값이 된다 — 재현이 아니라 같은 함수 |
| 깊이·자리·카메라 폴드 | 코어 `SetDepthStageReduction` · `PlaceFocusStageReduction` · `StageShotResponse` | 상태 이벤트의 끝 상태를 코어가 낸다 |
| 이징 함수(DOTween 포팅) | 코어 `EaseFunctions.Evaluate` | 상태 이벤트의 중간 프레임 |
| 스냅샷 되돌리기 · 정규 직렬화 · 내보내기 필터 · 등가 견본 방식 | `MotionEditor` · `MotionsJson` · `MotionExport` · `StageParityTests` | 그대로 따른다 |
| 블록 이동·스케일이 되는 시간 축 뷰 | `DopeSheetView` · `TimeSliderView` · `RangeSliderView` · `PlaybackClock` | 타임라인 뷰의 조작 관습·시계 |

| 자리 | 지금 | 묶인 이유 |
|---|---|---|
| `ViewportView.CurrentPose` | 고른 오브젝트 **하나**에 모션 **하나**만 얹는다. 나머지 오브젝트는 시작 상태로 선다 | "시간의 주인 = 모션 하나" |

| 씬 값 | 정지값(자리·층·보이기·카메라) | 시간에 따라 바뀌는 길이 없다 |
| 내보내기 | `motions.json` 하나 | 클립 산출물이 없다 |

### 1.3 런타임 쪽 사정 (이 저장소 밖 — 반입 코어에서 읽은 것)

- 런타임의 연출은 **커맨드 열**이다. 리듀서 어휘에 필요한 조각이 이미 있다: `motion(slot, name, mode?)` · `show` · `fade_in/out` ·
  `place*` · `size*` · `move_by`·`scale_by`·`rotate_by` · `face`·`pose` · `shot_zoom`·`shot_to`·`shot_reset` · 시간 커맨드(pause·Nfr).
  빠진 것은 **묶음과 시각**이다 — "이 여럿을 이 시간차로"를 이름 하나로 부르는 수단이 없다.
- `slot` 폴드는 `character` 리그만 세운다. 덤프의 리그는 `character`·`screenEffect` 둘이고 컷인·이모지 리그는 덤프에 없다.
  그래서 클립 v1의 출연자는 **캐릭터 리그 여럿 + 카메라**다. 컷인·이모지·화면전환은 리그 덤프와 슬롯 확장이 선행이다(§5 K7).
- 한 노드에 두 모션이 겹칠 때의 런타임 동작은 코어가 말하지 않는다(장부·트윈 쪽 일). 툴 초안은 **겹침을 막는다**(§3.4).

## 2. 설계 결정(제안)

### 2.1 클립 = 씬 위의 시간표

클립은 새 씬 그래프가 아니다. **씬(시작 상태) + 배역 + 트랙의 블록들**이다.

```
ClipAsset                         // 저작본 "clips": [...]
  name        "greet"             // 모션과 같은 이름 규칙 [a-z0-9_]+
  duration    2.5                 // 초. 비우면 마지막 블록의 끝
  scene       "scene"             // 미리보기 시작 상태 — 만들 때의 활성 씬이 적힌다(저작본 전용 — 산출물에 안 나간다)
  roles[]                         // 배역 — 산출물의 출연자 자리
    name      "a"                 // 클립 안의 이름. 재생할 때 슬롯에 묶인다
    rig       "character"
    object    "s1"                // 미리보기에서 이 배역을 맡는 씬 오브젝트(저작본 전용)
  tracks[]
    role      "a"  |  "@camera"
    blocks[]
      motion  { at, motion: "nod", mode: relative|absolute }          // 길이 = 그 모션의 Duration
      state   { at, kind, 값…, duration, ease }                        // K5 — §2.4
```

- **배역(role)** 을 두는 이유: 모션이 rigKind에 묶이고 슬롯에는 재생 때 묶이는 것과 같은 꼴이다. 클립도 특정 슬롯이 아니라
  "출연자 자리"에 묶여야 다른 장면에서 다시 쓸 수 있다. (2026-10-28에 뺀 `SceneObject.character` 배역과는 다른 물건이다 —
  그것은 focus 튜닝의 캐릭터 키였고, 이것은 클립의 인자다.)
- **모션은 참조한다.** 블록은 모션 이름만 든다. 키는 여전히 `motions[]`의 모션 하나에 있고 그래프 편집기가 그대로 고친다.
  모션을 고치면 그 모션을 쓰는 모든 클립이 따라온다. 블록 길이는 모션 길이다 — 자르기·속도·반복은 v1에 없다(§7).
- **mode는 블록이 정한다.** `motions/2`에서 mode는 쓰는 쪽(커맨드)의 인자다. 클립의 블록이 바로 그 "쓰는 쪽"이다.
  모션의 `previewMode`(뷰포트 렌즈)는 새 블록의 기본값으로만 쓴다.

### 2.2 미리보기 — 같은 함수를 시간 순으로

`ClipPreview.Pose(template, clip, t)`(새 순수 함수, `Mt.Authoring/Preview`):

1. `ScenePreview.Build`로 씬 시작 상태를 세운다(지금 그대로).
2. 시작 시각이 `t` 이하인 블록을 **시작 시각 순**(같으면 트랙 순, 트랙 안 순)으로 돈다.
3. 모션 블록은 `MotionPreview.Pose(tree, motion, t − at, null, 배역 오브젝트의 접두사)`를 그 블록의 mode로 부른다.
   끝난 restore 블록은 무변, 끝난 commit 블록은 마지막 키가 남는다 — `MotionPreview`의 끝 규칙이 이미 그렇다.
   앞 블록의 결과 트리가 뒤 블록의 시작값이다(런타임에서 `motion`의 시작값 = 그때의 노드 상태인 것과 같다).
4. 상태 블록(K5)은 끝 상태를 코어 폴드로 내고, 진행 중이면 시작·끝 사이를 `EaseFunctions`로 보간한다.

지켜야 할 성질(테스트로 못 박는다): **`t ≥ duration`의 포즈 = 클립을 시간 순 커맨드 열로 풀어 코어 `StageReducer.ApplyAll`이 접은 상태.**
이것이 "보이는 것 = 재생하는 것"의 클립판이고, 런타임이 `clip`을 어떻게 구현하든 정지 프레임은 이 표와 같아야 한다.

걸리는 것 하나: `MotionPreview.Pose`가 지금은 모션의 `PreviewMode`를 읽는다. mode를 인자로 받는 오버로드를 더한다(기존 호출은 그대로).

### 2.3 편집 흐름 — 두 층

| 층 | 시간의 주인 | 보는 것 | 하는 일 |
|---|---|---|---|
| **클립**(새로) | 클립 | 타임라인: 배역마다 한 줄, 모션 블록이 길이만큼의 막대 | 블록 놓기·끌기·mode·삭제, 전체 재생 |
| **모션**(지금) | 모션 하나 | 그래프·도프 시트 | 키 편집 — 지금과 같다 |

- 왼쪽 목록에 **클립** 묶음을 더한다. 클립을 고르면 아래 패널이 타임라인이 되고 시계·타임 슬라이더·레인지 슬라이더가 클립 길이를 본다.
- 블록을 **더블클릭**하면 그 모션의 그래프 편집으로 들어간다. 이때 뷰포트는 클립 문맥을 유지한다 — 다른 출연자는
  그 블록 시작 시각 + 모션 시각의 포즈로 서 있고, 고친 키가 바로 클립 안에서 보인다. Esc 또는 경로 표시로 클립에 돌아온다.
- 모션만 고르는 지금의 흐름은 그대로 남는다(클립 없이 모션 하나 — 기본).
- 조작 관습은 마야·도프 시트를 따른다: LMB 선택, MMB 드래그 이동, 시간 스냅 1/24초, Del, Ctrl+C/V, Ctrl+D.
  새 그림자 버튼을 두지 않는다. 단축키는 F1 표에 더한다.

### 2.4 상태 블록 — 씬 값이 시간에 따라 바뀐다

씬 오브젝트가 이미 가진 값만 다룬다. 새 어휘를 만들지 않고, 전부 코어 폴드가 있는 것이다.

| kind | 값 | 끝 상태를 내는 코어 | 런타임 대응(초안의 뜻) |
|---|---|---|---|
| `visible` | true/false | CanvasGroup alpha | `fade_in` / `fade_out` |
| `place` | 화면 지점 · focus 프리셋 | `PlaceFocusStageReduction` | `place` |
| `layer` | far·back·mid·front·close | `SetDepthStageReduction` | `size` |
| `offset` | x·y / 회전 / 배율 | `ScenePreview.ApplyPlacement`의 노드 | `move_by` · `rotate_by` · `scale_by` |
| `camera` | zoom · pan | `StageShotResponse` | `shot_zoom` · `shot_to` · `shot_reset` |

툴은 여전히 Yarn과 대본을 모른다. 블록은 **타입 있는 값**이고, 커맨드 대응은 규약 초안 문서에만 적는다.
중간 프레임은 런타임이 DOTween으로 트윈하는 것을 툴이 `EaseFunctions`로 따라 그리는 것이라, 끝 상태와 달리
**근사일 수 있다**(place는 커맨드 순간 한 번 풀리는 값이라 특히). 끝 상태만 등가를 약속하고 그 사실을 화면과 문서에 적는다.

### 2.5 저장과 산출물

- **저작본**: `motion-authoring/2`에 선택 항목 `clips[]`를 더한다(씬을 `/1`에 더했던 선례와 같다). 없으면 지금 문서 그대로다.
- **산출물은 둘로 나눈다.** `motions.json`(`motions/2`)에는 **아무것도 더하지 않는다** — 바이트 동일 골든과 무대 등가 견본이 그대로 선다.
  클립은 새 파일 `clips.json`(`scene-clip/1`, 초안)으로 나간다. 정규 직렬화는 `MotionsJson`의 규칙을 따른다(diff 안정).
- **초안 규약의 모양**(런타임과 합의 전 — 바뀔 수 있다고 파일 머리에 못 박는다):

```json
{ "schema": "scene-clip/1-draft",
  "clips": [ { "name": "greet", "duration": 2.5,
    "roles": [ { "name": "a", "rig": "character" }, { "name": "b", "rig": "character" } ],
    "events": [
      { "t": 0.0, "role": "a", "kind": "motion", "motion": "bow", "mode": "absolute" },
      { "t": 0.5, "role": "b", "kind": "motion", "motion": "nod", "mode": "relative" } ] } ] }
```

  트랙은 저작의 편의라 산출물에서는 시각 순 `events[]` 한 줄로 편다. 재생 커맨드는 `<<clip greet s1 s2>>`(배역 순서대로 슬롯)를 제안한다.
  정지 프레임 폴드 = events를 시각 순으로 기존 폴드에 넘긴 것 — 런타임에 새 수학이 필요 없다.
- **규약 초안 문서** `docs/clip-contract-draft.md`를 K6에서 쓴다 — 무대 저장소 `motion-contract.md`의 짝. 런타임이 구현할 때의 정본 후보다.

## 3. 규칙(초안) — 검증이 막는 것과 알리는 것

1. 클립 이름은 모션과 같은 규칙이고 클립끼리 겹치지 않는다. 배역 이름은 클립 안에서 겹치지 않는다.
2. 모션 블록의 모션은 문서에 있어야 하고 그 `rig`가 배역의 `rig`와 맞아야 한다(`CanWear`와 같은 판정). **막는다.**
3. 블록은 `0 ≤ at`이고 `at + 길이 ≤ duration`. **막는다**(돕는 손: 길이를 마지막 블록 끝에 맞추기).
4. 같은 배역의 **같은 노드·종류**를 쓰는 두 모션 블록은 시간이 겹치면 안 된다. **막는다** — 런타임 동작이 정의되지 않았다.
   다른 노드를 쓰는 블록은 겹쳐도 된다(고개 끄덕임 + 몸 흔들기).
5. 참조하는 모션이 내보내기 검증에 걸리면 그 클립도 막힌다(`MotionExport`의 필터와 같은 방식 — 고른 것의 문제만 막는다).
6. 알림(막지 않음): 미리보기 배역에 오브젝트가 안 묶였다(또는 씬에 없다 · 리그가 다르다) · 빈 클립.
   ("restore 뒤의 relative" 알림은 K2에서 뺐다 — 끄덕임 두 번처럼 흔하고 옳은 배치라 소음이다.)

모션을 지우거나 이름을 바꾸면: 이름 바꾸기는 블록의 참조를 **같은 되돌리기 칸에서** 따라 바꾼다. 지우기는 블록을 남기고 검증이 소리를 낸다
(조용히 같이 지우지 않는다 — `PLAN.md` §4의 "조용히 맞는 척하지 않는다").

## 6. 소유자에게 묻는 것 (K0)

1. **배역을 둘 것인가.** 제안은 둔다(§2.1 — 재사용). 대안은 블록이 씬 오브젝트 id를 직접 가리키는 것 — 단순하지만 클립이 씬 하나에 묶인다.
2. **상태 블록(K5)을 타입 있는 값으로.** 제안은 §2.4(씬이 이미 가진 다섯 값). 대안은 커맨드 이름·인자를 그대로 싣는 것 — 런타임 어휘 전부를
   바로 쓰지만 "툴은 커맨드를 모른다"는 결정을 깬다. 제안은 그 결정을 지킨다.
3. **산출물 파일.** 제안은 `clips.json`을 따로(§2.5). 대안은 `motions.json`에 `clips`를 더하고 `motions/3` — 파일은 하나지만 바이트 동일 골든과 로더를 흔든다.
4. **재생 커맨드의 꼴**(초안 문서에 적을 것): `<<clip 이름 슬롯…>>` 위치 인자 / `a=s1` 이름 인자. 그리고 클립이 끝날 때까지 대본이 기다리는가.
5. **저작본 스키마.** 제안은 `/2`에 선택 항목. 대안은 `motion-authoring/3`으로 올리고 `/2`를 읽기 — 옛 툴이 새 파일을 조용히 여는 일을 막는다.
6. **자르기·속도·반복.** 제안은 v1에 없다(§7). 반복만이라도 필요하면 블록에 `repeat`를 K4에 더한다.
7. **K1~K4 뒤의 순서.** 상태 블록(K5) 먼저인가 내보내기 초안(K6) 먼저인가.

## 7. 하지 않는 것 (v1)

- 블록 자르기·속도 배율·블렌딩·교차 페이드 — NLA(마야 Time Editor)의 영역이고 런타임에 대응물이 없다.
- 애니메이션 레이어 — `PLAN-maya.md`의 결정 그대로.
- 오브젝트끼리의 부모·자식, 클립 안의 클립(중첩).
- 컷인·이모지·화면전환·배경 연출 — 리그 덤프와 런타임 슬롯 확장이 선행이다. 타임라인은 리그가 생기면 줄이 늘 뿐이다.
- 오디오·대사 타이밍. Yarn 내보내기. 씬을 런타임 산출물로 내보내기.
- 클립 층에서의 포즈 편집·Auto Key — 키는 모션 층에서만 놓는다.
- 코어 사본 수정. 필요한 것이 코어에 없으면 `Mt.Authoring`에서 적응하고 무대 저장소에 요청으로 적는다.

- **카메라 모션**(소유자 요청 "카메라도 키와 커브로", 2026-11-09) — `PLAN.md` §8의 "카메라 채널"을 툴 쪽에서 먼저 연 것:
