## 2. 소유자와 일하는 법 (앞 세션에서 굳은 것)

`CLAUDE.md`의 관습에 더해, 대화로 정해진 것들이다.

- **단계는 소유자가 "진행"이라고 할 때 시작한다.** 다음 단계를 스스로 시작하지 않는다. 끝나면 무엇을 했는지 보고하고 멈춘다.
- **이 저장소는 에이전트가 커밋하고 `dev`에 푸시까지 한다.** 한 번에 하나, 전체 테스트가 통과한 채로. 커밋 메시지는 한국어 "무엇을 왜" 한 줄 + 본문.
- **런타임(`ked-presentation-runtime`)은 소유자가 직접 커밋한다.** 거기서는 고치고 보고만 한다(커밋 · 푸시하지 않는다). 그쪽 일도 지시가 있을 때만.
- **코어 사본(`src/Ked.Presentation.Core`)은 고치지 않는다.**
- **PR은 요청받았을 때만.**
- 결정과 상태는 하고 있는 계획서(`PLAN-cleanup.md`)에 적는다. 소유자가 권고와 다르게 정한 것 · 지시 없이 고친 것은 "적어 둘 것"에 까닭과 함께.
- 화면을 고쳤으면 **그림으로 뽑아 눈으로 보고**, 보고에 그림을 붙인다(소유자는 화면으로 판단한다).
- 소유자는 한국어 존댓말로 짧게 지시한다. 말이 두 가지로 읽히면 **지우는 일은 묻고 한다** — 앞 세션은 "예전 문서를 정리"를 한 번 잘못 읽었다(§5).
- 소유자의 이메일 등 개인 정보를 커밋 · 문서 · 외부 서비스에 적지 않는다.

소유자가 자주 하는 판단: 안 쓰는 것 · 옛것을 위한 코드는 **남기지 않는다**(§5). 마야의 관습을 따른다. 사람이 쓰는 화면은 **보이는 대로 직관적**이어야 한다.

## 4. 다음에 할 일

### 4-1. 3단계 — 불편 고치기 (하는 중)

`PLAN-cleanup.md` §6이 정본이다. 처음의 셋(`mt validate`가 문제를 한 번에 다 말하기 · 없는 그림 파일 알리기 · `mt`의 만드는 명령)은 고쳤다.
그 뒤 점검으로 찾은 것이 A(일을 잃을 수 있는 것 — 닫을 때 묻지 않는다 등) · B(틀린 것을 말해 주지 않는 것 — 키 이름의 오타 등) · C(번거로운 것) · D(화면에서 헷갈릴 만한 것)로 적혀 있다 — **아직 고치지 않았다.** 소유자가 순서를 정하면 하나씩 한다.

여기에 **소유자가 설명서를 따라 해 보며 찾은 것**과 **다른 세션(연출 추출기 — 동영상을 읽고 모션을 만드는 AI)이 `AUTHORING-FILES.md`로 만들어 보며 걸린 것**이 더해질 것이다.

### 4-2. 소유자가 아직 확인하지 않은 것

앞 세션은 화면을 헤드리스로만 봤다. 아래는 사람이 실제 창에서 봐야 한다 — 소유자가 말해 오면 3단계의 재료다.

- 클립 타임라인의 오른쪽 단추 메뉴(상태 블록을 걷은 뒤).
- 새 이모지 창의 끌어다 놓기와 파일 고르는 창, 트윈머신 창이 위에 머무는가 · 자리를 기억하는가.
- 그래프의 종류별 칸에서 키 · 손잡이 끌기.
- 그림 설명서 26장의 번호 자리 — 전부를 낱낱이 보지는 못했다.
- `USER-GUIDE.md` · `docs/guide/README.md`를 처음부터 따라 했을 때 막히는 곳.

### 4-3. 남은 빚 (급하지 않다)

- 코어 사본의 전체 재반입 — 지금은 옛 분리본 기준에 이모지 파일만 정본에서 얹은 상태다(`src/Ked.Presentation.Core/vendoring.md`).
- Windows 패키지와 그 CI.

## 5. 조심할 것 — 앞 세션이 걸린 데

- **"마이그레이션은 두지 않는다."** 소유자가 분명히 정했다(2026-11-12): 옛 파일을 살리려는 방어 코드 · 폴백 경로 · 호환용 멤버를 남기지 않는다. 앞 세션은 기능을 지우며 "예전 문서도 읽히게" 읽을 때 버리는 코드를 넣었다가, 그리고 설정 파일을 옛 자리에서 읽어 오게 했다가 **도로 다 뺐다.** 형식을 바꾸거나 기능을 지울 때 옛 문서를 옮겨 읽는 코드를 넣지 않는다 — 저작본은 `motion-authoring/2`가 아니면 거부하고, `motions.json`은 `motions/2`가 아니면 읽지 않는다.
- **"예전 파일"은 지우지 않았다.** `docs/history/`(끝난 계획서 12개 + 정리 전 README), PC의 자동 저장본, PC의 옛 설정 파일(`%APPDATA%\ked-motion-tool\` — 형제 툴이 쓴다) — 소유자가 **남긴다**고 했다.
- **컨트롤러 표의 별칭**(`controllers.json`의 `aliases`)은 옛 파일용이 아니다. 런타임의 지금 견본 `nod`가 그 노드(`Track_Move_Y`)를 쓴다 — 지우지 않는다.
- **설명서는 코드와 같이 간다.** 저작본의 형식 · 검증 문구 · `mt`의 출력을 바꾸면 `AUTHORING-FILES.md`와 `examples/authoring/`을(테스트 `AuthoringExampleTests`가 지킨다), 화면의 배치 · 단추 이름을 바꾸면 `USER-GUIDE.md`와 그림 설명서를 같이 고친다.
- **그림 설명서의 그림은 손으로 고치지 않는다** — 다시 만든다(§6). 화면의 배치가 바뀌면 `tools/guide-figures.py`의 자리(1600×960 기준 px)를 고쳐야 번호가 맞는다.
- **화면 그림을 뽑을 때 전체 테스트를 `MT_RENDER_DIR`과 같이 돌리지 않는다**(들쭉날쭉 실패한다) — `--filter Shots`로만.
- 헤드리스의 한계: 보통의 실행은 PNG를 읽지 못한다(그림을 뽑을 때만 Skia로 그린다). 모드를 바꾼 뒤에는 `Dispatcher.UIThread.RunJobs()`. 되돌리기는 문서 객체를 바꾸니 `Undo()` 뒤에는 자산을 다시 찾는다. 설정 · 단축키 창은 헤드리스에서 열지 않는다. (`MAINTENANCE.md` §5 · §6)
- 안 쓰는 using은 보통 빌드가 막지 않는다 — 훑는 법은 `PLAN-cleanup.md` §4의 "적어 둘 것".
- 그림 설명서의 초상(`docs/guide/art/portrait.png`)은 설명서용으로 그린 것이다. 런타임의 초상 샘플은 저장소에 넣지 않았다.

## 6. 자주 쓰는 명령

```bash
dotnet build KedMotionTool.sln -c Release
dotnet test  KedMotionTool.sln -c Release --no-build        # 요약 줄이 셋(세 프로젝트) 나오는지 센다

# 화면을 그림으로 뽑고, 그림 설명서의 그림을 다시 만든다(Python + Pillow)
MT_RENDER_DIR=<폴더> dotnet test tests/Mt.App.Tests -c Release --filter Shots
python3 tools/guide-figures.py <폴더> docs/guide/img

# 이모지 예시 문서를 다시 쓴다(빌더 tests/Mt.Authoring.Tests/EmojiExamples.cs를 고친 뒤)
MT_WRITE_EXAMPLES=1 dotnet test tests/Mt.Authoring.Tests -c Release --filter EmojiExampleTests

# 창 없이 확인 · 내보내기
dotnet run --project src/Mt.Cli -- validate examples/authoring/motions.motion-authoring.json
```

앞 세션의 작업 환경에서만 필요했던 것(다음 세션은 필요 없을 것이다): 그 환경에는 `netstandard2.1` 참조 팩이 없어 빌드할 때마다 코어 사본의 csproj를 **작업 공간에서만** `net10.0`으로 바꿨다가 되돌렸다. 저장소에는 한 번도 들어가지 않았다 — `Ked.Presentation.Core.csproj`가 `netstandard2.1`이 아닌 채로 커밋되어 있으면 잘못된 것이다.

## 8. 연관된 것

- **`ked-presentation-runtime`** — 정본(코어 · 리그 덤프 · 이모지의 정의와 재생). 소유자가 커밋한다.
- **`ked-motion-tool-extend`** · **`ked-motion-tool-screenTransition`** — 형제 툴. 여기서는 그 둘의 일을 하지 않는다.
- **연출을 추출하는 다른 세션** — 동영상을 읽고 연출 카드 · 모션 카드를 만든다. 그 세션이 이 툴의 파일을 쓸 때 보는 것이 `AUTHORING-FILES.md`다. 그쪽에서 걸린 것이 3단계의 재료가 된다.
- 그림 설명서는 소유자가 대화에서 볼 수 있게 웹 페이지로도 띄워 두었다(소유자의 계정에 있다). 저장소의 `docs/guide/`가 정본이고, 그 페이지는 사본이다 — 그림 설명서를 고치면 소유자에게 다시 띄울지 묻는다.
